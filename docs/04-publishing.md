# 배포 가이드

## 버전 규칙

`MAJOR.MINOR.PATCH` 를 쓴다.

- **PATCH** — 텍스처 교체, 설명 문구 수정 등 밸런스에 영향이 없는 변경
- **MINOR** — 수치 조정, 부품 추가
- **MAJOR** — 기존 로켓 세이브가 깨질 수 있는 변경(부착점 위치 변경, 부품 ID 변경 등)

부품 ID(`meridian_engine`)는 **한 번 배포하면 바꾸지 않는다.** ID 가 바뀌면 그 부품을 쓴 유저의 로켓이 깨진다.

## 릴리스 절차

1. `python3 tools/validate_parts.py` 통과 확인 (종료 코드 0)
2. `python3 tools/spec_sheet.py` 로 문서 갱신
3. `docs/03-testing-checklist.md` 를 실제로 채운다 — E2(안드로이드 실기기)까지 포함
4. `.pack` 을 저장소에 커밋하고 태그(`v1.0.0`)를 단다
5. GitHub Releases 에 `.pack` 을 첨부하고, 릴리스 노트에 다음을 적는다
   - 지원 플랫폼(PC/모바일)과 확인한 SFS 버전
   - 부품 수치 요약표
   - 알려진 문제
6. 배포 채널: SFS 포럼(jmnet.one/sfs/forum) 커스텀 파트 게시판, itch.io, SFS 모드 데이터베이스 등

## 배포물에 반드시 적을 것

- **어떤 SFS 버전에서 테스트했는지.** 게임 업데이트로 모듈 구조가 바뀌면 파트팩이 깨질 수 있다.
- **코드 모드가 아니라 파트팩이라는 점** — 모바일에서도 된다는 뜻이므로 설치 안내가 달라진다.
- 새 자원 타입을 쓰지 않는다는 점(스톡 연료탱크와 호환).

## 라이선스

MIT 를 권장한다. 텍스처를 외부에서 가져다 쓴 경우 그 라이선스가 우선이므로,
직접 만든 것과 가져온 것을 `assets/` 안에서 구분해 기록할 것.
현재 `assets/textures/*.png` 는 `tools/make_texture_template.py` 가 생성한 것으로 전부 자체 제작물이다.
