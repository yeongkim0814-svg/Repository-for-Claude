# 설계서 — Meridian 엔진

## 1. 왜 이 부품인가

SFS 스톡 엔진 5종의 실제 수치를 뽑아보면 빈 자리가 하나 보인다.

| 엔진 | 추력 | ISP | 질량 | 추력/질량 | thrustPosition |
|---|---|---|---|---|---|
| Kolibri | 15 | 260 | 0.5 | 30.0 | (0, -1.5) |
| Valiant | 40 | 280 | 2.0 | 20.0 | (0, -2.0) |
| Frontier | 100 | 290 | 6.0 | 16.7 | (0, -3.5) |
| Hawk | 120 | 240 | 3.5 | 34.3 | (0, -3.0) |
| Titan | 400 | 240 | 12.0 | 33.3 | (0, -4.0) |

출처: 공식 Modding Toolkit(`Stef-Moroyna/Spaceflight-Simulator--ModdingToolkit`)의
`Assets/Resources/Parts/Engines/*.prefab` 에 직렬화된 `EngineModule` 값. `parts/stock-reference.json` 에 기록되어 있다.

관찰:

- **ISP 상한이 290**이다. 그 이상 효율을 내는 선택지가 없다.
- 스톡은 "추력이 크면 효율이 낮다"(Hawk/Titan)와 "작으면 효율이 좋다"(Valiant/Frontier)가 섞여 있지만,
  **효율을 위해 무게를 지불하는** 축은 비어 있다.

그래서 Meridian 은 **ISP 330 / 추력 60 / 질량 5.0 t** 로 정했다. 추력/질량비 12.0 은 게임 내 최저값이다.

## 2. 밸런스 규칙

새 부품이 스톡을 무의미하게 만들지 않는 것이 유일한 하드 룰이다. `tools/validate_parts.py` 가 이를 강제한다.

> **ISP 가 스톡 최고치(290)를 넘으면, 추력/질량비가 스톡 최저치(16.7)보다 낮아야 한다.**

Meridian 은 ISP 330(> 290)이므로 추력/질량비 12.0(< 16.7) 조건을 만족한다.
이 규칙을 어기면 검증기가 종료 코드 1로 실패한다.

## 3. 실제 성능 — 두 가지 표준 스테이지

검증기가 계산하는 값이다 (`Δv = ISP × 9.80665 × ln(m0/mf)`, 탱크 건조질량 10%).

**소형 상단** (연료 20 t + 페이로드 5 t)

| 엔진 | Δv (m/s) | 초기 T/W |
|---|---|---|
| Kolibri | 3120 | 0.59 |
| Valiant | 3017 | 1.48 |
| Frontier | 2471 | 3.23 |
| **Meridian** | **2965** | **2.00** |

**중형 전이단** (연료 90 t + 페이로드 20 t)

| 엔진 | Δv (m/s) | 초기 T/W |
|---|---|---|
| Kolibri | 3367 | 0.14 |
| Valiant | 3527 | 0.36 |
| Frontier | 3408 | 0.86 |
| Hawk | 2943 | 1.06 |
| **Meridian** | **3944** | **0.52** |

읽는 법:

- **소형 단에서는 Meridian 이 최고가 아니다.** 5 t 이라는 자체 질량이 25 t 짜리 단에서는 너무 무겁다.
  Kolibri(3120)나 Valiant(3017)가 Δv 로는 앞선다 — 스톡 소형 엔진의 자리는 그대로 남는다.
- **중형 전이단부터 확실히 앞선다.** 3944 m/s 로 2위 Valiant(3527)보다 +12%, Frontier 대비 +16%.
  대신 초기 T/W 0.52 라 지구 이륙은 불가능하다.

즉 "언제 써야 하는지가 분명한 부품"이 됐다. 이게 설계 목표였다.

## 4. 구현 방침

| 결정 | 이유 |
|---|---|
| 파트팩(`.pack`)으로 배포 | 코드 모드(.dll)는 PC 전용. 모바일 유저까지 닿으려면 파트팩이어야 한다. |
| 새 ResourceType 을 만들지 않음 | 스톡 액체연료(GUID `228bca42e456ecb4cb87cdd837fa81fe`)를 그대로 쓰면 스톡 탱크와 바로 호환되고, 별도 탱크 부품을 만들 필요가 없다. |
| C# 코드 없이 동작하도록 | 파트팩에 코드 어셈블리를 넣을 수는 있지만 모바일(IL2CPP)에서 실행이 보장되지 않는다. 엔진의 모든 기능은 툴킷 모듈 조합만으로 성립해야 한다. `unity/` 의 C# 은 어디까지나 선택적 확장이다. |
| 스톡 `Engine Frontier.prefab` 복제로 시작 | 부착점·콜라이더·이펙트·변수 배선이 이미 되어 있어 실수 여지가 적다. |
| 짐벌 torque = throttle × 3 | Frontier/Valiant 는 ×5, Kolibri 는 ×2. 상단 엔진이므로 중간보다 약하게. |

## 5. 형상과 부착점

- 크기: 폭 2 × 높이 3 (스톡 Frontier 와 같은 급)
- 부착점: 위 `(0, 0)` breakForce 1500, 아래 `(0, -3.0)` breakForce 800
- 콜라이더: 본체 사다리꼴 + 노즐 사다리꼴 두 개 (`parts/meridian.part.json` 의 `colliders`)
- 화염 위치는 `thrustPosition (0, -3.0)` 과 일치시켜야 한다 — 어긋나면 불꽃이 노즐에서 떨어져 나온다.

## 6. 변경 이력 / 열린 항목

- 이름과 수치는 **인게임 테스트 전의 제안값**이다. 실제로 날려보고 조정한다.
- 조정 절차: `parts/meridian.part.json` 만 고치고 → `tools/validate_parts.py` → `tools/spec_sheet.py`.
  문서의 표는 검증기 출력을 옮긴 것이므로, 수치를 바꿨으면 이 문서의 3절 표도 함께 갱신할 것.
- 후속 후보(1차 검증 이후): 같은 계열의 소형/대형 파생형, 전용 스커트 구조물, 이온 엔진(새 자원 타입 필요).
