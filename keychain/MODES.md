# 모드 설계 v0.3

전제 (보드 변경: nRF52840 Sense → **ESP32 계열**, 마이크·스피커 미사용)
- 화면: 0.96" SSD1306 2색 OLED 128×64 (**0–15행 노랑 / 16–63행 파랑**, 색은 하드웨어 고정)
- 보드: **Seeed XIAO ESP32-C3** 기준 → Wi-Fi + BLE 5, LiPo 충전 회로 내장, USB-C. **IMU는 내장이 아니므로 외장 모듈**(LSM6DSO/LSM6DS3TR-C 브레이크아웃, I²C)을 OLED와 같은 버스에 물림
- RTC: 별도 칩 없이 ESP32 내부 RTC 타이머 사용(딥슬립 중 시간 유지는 되지만 수정발진자가 없어 하루 수십 초 오차 가능 — 시계 용도가 아니라 "밤/낮 대략 구분" 정도로만 사용)
- **마이크·스피커 없음 → 사운드 관련 모드 전부 제외.** 알림은 부저(선택)로만.
- 규칙: **얼굴과 액체는 동시에 나오지 않는다.** 한 번에 한 모드만 화면 전체를 쓴다.

> 보드 교체로 잃는 것: IMU가 칩 내장이 아니게 되어 부품 하나·배선 몇 가닥이 늘고, ESP32 계열은 nRF52840보다 딥슬립 전류가 높다(6절 참고). 대신 Wi-Fi가 생기고, 국내 구하기·문서·커뮤니티 예제가 훨씬 많다.

## 1. 부품 → 가능한 기능 (추천 근거)

| 부품 | 여기서 공짜로 얻는 것 | 이걸로 만들 수 있는 모드 |
|------|----------------------|--------------------------|
| IMU 가속도 | 중력 방향, 자유낙하, 충격 | 액체, 모래시계, 수준기, 낙하 측정 |
| IMU 자이로 | 회전 속도 | 어지러움 반응, 회전 측정 |
| IMU 모듈 **내장 기능**(칩 하드웨어, MCU와 무관하게 동작) | 만보기, 더블탭, 자유낙하, 6방향 자세, 움직임 인터럽트 핀 | IMU 칩이 걸음을 세는 동안 ESP32는 계속 딥슬립 → 펫 성장, 제스처 입력 |
| Wi-Fi + BLE | 폰과 통신, (선택) 시각 동기화 서버 접속 | 시간 동기화, 폰 찾기, 설정 변경 |
| CHG 핀 + ADC | 충전 중 여부, 배터리 전압 | 충전 화면, 배터리 표시 |

> 보드 교체로 사운드 모드는 없앤다. 대신 IMU 칩 자체 걸음 수 기능은 그대로 살아있다 — MCU가 아니라 **IMU 칩**이 세는 것이므로 보드가 바뀌어도 전력 이점은 유지된다. 다만 ESP32는 그 값을 읽으러 깨어날 때 nRF52840보다 더 많은 전류를 쓴다(6절).

## 2. 모드 구성

모드는 링 구조로 순환한다: **펫 → 액체 → 모래시계 → 물리 랩 → (펫)**
시스템 화면(충전·수면·설정)은 링 밖에 있고 조건에 따라 자동 진입.

### 화면 공통 규칙: 노랑 띠 = 정보, 파랑 영역 = 내용
2색 OLED의 제약을 역할 분리로 쓴다. 상단 16행(노랑)은 모드 아이콘·배터리·모드별 핵심 숫자 1개, 하단 48행(파랑)은 모드의 본 화면. 액체 모드만 예외로 몰입을 위해 2초 뒤 노랑 띠를 숨기고 액체가 64행 전체를 쓴다(띠에 들어온 액체는 노랗게 보임 = 하드웨어 특성을 연출로).

---

### M1. 펫 (얼굴) — 기본 홈 · MVP
| 입력 | 반응 |
|------|------|
| 가만히 | 깜빡임(지수분포 간격), 두리번, 한숨 |
| 기울기 | 눈이 아래쪽을 봄 |
| 흔들기 / 회전 | 놀람 / 어지러움(@_@) |
| 뒤집기 | 당황 |
| 걸음 수(IMU 만보기) | 오늘 걸음 → 기분·에너지. 목표 달성 시 기쁨 표정 |
| 시간(내부 RTC, 대략) | 밤 시간대엔 졸린 눈, 아침 첫 움직임에 기지개 (정밀 시계 아님) |

노랑 띠: 오늘 걸음 수 또는 기분 아이콘.

### M2. 액체 — MVP
- 1D 높이장 출렁임(시뮬레이터 구현분 그대로).
- 흔들면 거품, 뒤집으면 반대편으로 쏟아짐, 자유낙하 시 흩어짐.
- 옵션: **액체 양 = 배터리 잔량**. 보기만 해도 배터리가 보이는 계기.
- 매달린 상태에선 물리적으로 거의 안 출렁이므로 **기울기 게인 ×3–5** 기본 적용.

### M3. 모래시계 타이머 — MVP (공부용)
- **뒤집으면 시작.** 위쪽에 모래(입자) 더미, 목 부분으로 한 알씩 떨어짐.
- 기본 25분/5분(뽀모도로). 떨어지는 속도 = 남은 시간 비례이므로 정확한 타이머와 실제 모래 느낌을 같이 가짐.
- 노랑 띠: 남은 시간 `mm:ss`.
- 액체와 같은 "중력 벡터" 입력을 쓰지만 표현은 입자(모래) → 엔진 재사용, 느낌은 다름.
- 한계: 부저가 없으면 끝나도 **알릴 방법이 화면뿐**. 주머니 속이면 모름 → 5절 추가 부품 참고.

### M4. 물리 랩 — 2차 (센서를 그대로 보여주는 모드)
서브화면 3개(더블탭으로 전환):
1. **수준기/경사계**: 기포 + 각도(°). 경사면 실험에서 각도 측정.
2. **g-미터**: 현재 |a|, 최대값 기록. 엘리베이터 출발/정지, 버스 급정거의 겉보기 무게 변화 측정.
3. **낙하 타이머**: 자유낙하(|f|≈0) 지속 시간 t 측정 → `h = ½gt²` 표시. (쿠션 위로만!)

→ 교과서 식을 내 기기로 직접 검증하는 모드. 측정 오차(샘플링 주기, 센서 잡음)까지 볼 수 있다.

### M5. 주사위·매직볼 — 3차(보너스, IMU만)
흔들면 주사위 굴러가는 애니메이션 → 결과. 코드 적고 친구한테 보여주기 좋음.

### 시스템 화면(링 밖)
| 화면 | 진입 조건 | 표시 |
|------|----------|------|
| 충전 | CHG 핀 Low | 액체가 차오르는 배터리(액체 엔진 재사용) |
| 수면 | N초 무움직임 (타이머 동작 중 제외) | 화면 OFF, IMU 움직임 인터럽트 대기 |
| 저전압 | 배터리 < 3.4 V | 펫이 지친 얼굴 + 배터리 아이콘 깜빡 |
| 설정 | 버튼 5초 | 밝기, 잠드는 시간, 게인, BLE 켜기 |

## 3. 전환: 얼굴 ↔ 액체를 잇는 연출
동시에 안 나오는 대신 **바뀌는 순간**을 연결한다.
- 펫 → 액체: 눈이 녹아내림. 눈 픽셀을 입자로 바꿔 중력 방향으로 떨어뜨리고, 바닥에 쌓이면 높이장 액체로 넘김.
- 액체 → 펫: 반대로 액체가 가운데로 모여 두 눈 모양으로 솟아오름.
- 나머지 모드 전환: 노랑 띠에 모드 이름이 0.8초 슬라이드, 파랑 영역은 가로 와이프.

---

## 4. 입력 설계
키체인은 **하루 종일 부딪힌다.** 더블탭·흔들기 같은 IMU 제스처만으로 모드를 바꾸면 주머니 속 충격으로 오작동이 잦다. 그래서 추천:

**택트 버튼 1개(측면, 버튼 윗면이 케이스보다 0.3 mm 들어가게 = 오작동 방지)**
| 입력 | 동작 |
|------|------|
| 짧게 | 다음 모드 |
| 길게 1 s | 모드 내 동작(타이머 시작/리셋, 최대 g 리셋, 영점) |
| 5 s | 설정 |
| IMU 더블탭 | 모드 내 서브화면 전환(물리 랩) — 오작동해도 피해 작음 |
| 뒤집기 | 모래시계 시작 |
| 흔들기 | 모드별 반응 |

버튼 없이 가는 경우: 더블탭 = 다음 모드, 단 "화면이 위를 향하고 0.5 s 정지한 상태에서의 더블탭"만 인정 (주머니 속 충격 걸러내기). 오작동은 줄지만 0이 되진 않음.

## 6. 모드별 전력 (200 mAh 기준, 대략, ESP32-C3 기준)
| 모드 | 켜진 픽셀 | 추가 부하 | 전류 | 연속 사용 |
|------|----------|----------|------|----------|
| 펫 | ~8% | – | ~25–35 mA | ~6–8 h |
| 액체 | 15–25% | 물리 계산 | ~28–38 mA | ~5–7 h |
| 모래시계 | ~10% | – | ~25–35 mA | ~6–8 h |
| 물리 랩 | ~10% | IMU 고속 샘플 | ~26–36 mA | ~6–8 h |
| 딥슬립(화면 OFF) | 0 | IMU 인터럽트 대기 | ~0.1–1 mA | 수 주 |

(OLED 전류는 켜진 픽셀 수에 거의 비례 → 채움 패턴 "디더 50%"가 솔리드보다 약 절반. **화면 켜짐 전류가 nRF52840 안일 때보다 3–5배 높다** — ESP32-C3는 Wi-Fi/BLE 라디오 대기 전력 때문에 액티브 모드 자체가 20 mA대에서 시작한다. Wi-Fi를 코드로 아예 끄고(`WiFi.mode(WIFI_OFF)`) BLE만 필요할 때 켜면 액티브 전류를 10 mA대까지 낮출 수 있다. 딥슬립은 반대로 nRF52840보다 더 낮게도 갈 수 있어(수 µA대 칩 스펙) 실측으로 확인 필요.)

## 7. 구현 우선순위
1. **MVP**: 펫, 액체, 모래시계, 수면, 충전 화면, 버튼 1개, 펫↔액체 녹는 전환
2. **2차**: 물리 랩, 걸음 수 → 펫 기분, Wi-Fi 끄고 BLE만 쓰는 저전력 튜닝
3. **3차**: BLE(시간 동기화·설정), 주사위, 부저 효과음
