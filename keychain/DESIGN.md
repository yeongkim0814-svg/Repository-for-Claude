# 도트 페이스 키체인 — 설계 v0.1 (보관됨)

> **이 문서는 v0.1 기록으로 남겨두며 더 이상 갱신하지 않는다.**
> OLED + 다중 모드(액체/모래시계/물리 랩) 구성이었으나, **E-Ink 디스플레이로 교체하고 기능을 얼굴+액체 2개로 좁힌 v2 설계**로 대체됐다.
> 현재 설계는 [`DESIGN_V2.md`](DESIGN_V2.md) 참고. `MODES.md`도 v1 다중 모드 기준이라 함께 보관됨.

> 목표(v0.1 당시): 손바닥보다 작은 키체인 안에 **도트 얼굴 + 기울이면 출렁이는 액체 + 가만두면 살아 움직이는 아이들 애니메이션**을 한 화면에 구현한다.
> 외장은 3D 프린팅, 일부 전선은 **의도적으로 노출**해서 디자인 포인트로 쓴다.

## 2. 물리 원리 — 왜 이렇게 구현하는가

### 2.1 가속도계는 "중력"이 아니라 "비중력 힘"을 잰다
가속도계가 재는 값은 고유가속도(proper acceleration)

$$\vec a_{\text{meas}} = \vec a - \vec g$$

- 책상 위에 정지: $\vec a = 0$ → 측정값 $= -\vec g$ (위쪽 1g). 즉 **"아래" 방향 = 측정값의 반대 방향**.
- 자유낙하: $\vec a = \vec g$ → 측정값 0. (그래서 떨어뜨림 감지가 가능 → "으악" 표정 트리거로 쓸 수 있다.)

### 2.2 액체 수면의 방향 = 유효중력에 수직
병(=키체인) 좌표계는 가속하는 비관성계이므로, 그 안의 액체는 **유효중력** $\vec g_{\text{eff}} = \vec g - \vec a$ 를 느낀다. 정지 평형에서 수면은 $\vec g_{\text{eff}}$에 수직이고, 화면 평면(x: 가로, y: 세로)에서 수면 기울기는

$$\tan\theta = \frac{g_{\text{eff},x}}{g_{\text{eff},y}}$$

그런데 $\vec g_{\text{eff}} = -\vec a_{\text{meas}}$ 이므로 **가속도계 값을 부호만 바꿔 그대로 "중력 벡터"로 쓰면 된다.** 이게 시뮬레이션의 입력 전부다.
(고1 물리의 "가속하는 버스 안 물컵 수면이 기우는 현상"과 정확히 같은 식.)

- 어디까지 맞나: 천천히 기울일 때(준정적) 완벽히 맞음.
- 어디서 깨지나: 빠르게 흔들면 수면이 즉시 평형으로 가지 못하고 **진동(sloshing)** 한다 → 2.3의 동역학이 필요.
- 화면 평면에 수직인 성분 $g_z$ 는 2D 화면에 표현 불가. 화면이 하늘을 보고 누우면 $g_x, g_y \approx 0$ → 액체가 "어디로도 안 흐르는" 상태가 된다. 이때는 액체를 화면 전체에 얇게 퍼뜨리거나 잔물결만 두는 식으로 처리.

### 2.3 출렁임: 1D 높이장(height field) 파동 방정식
수면을 가로 방향 $N$개(예: 32칸) 기둥 높이 $h_i$로 표현하고 감쇠 파동방정식을 푼다.

$$\frac{\partial^2 h}{\partial t^2} = c^2 \frac{\partial^2 h}{\partial x^2} - \gamma \frac{\partial h}{\partial t} + F_{\text{tilt}}(x,t)$$

- $c^2 \partial_x^2 h$: 이웃 기둥보다 높으면 내려오려는 복원력(얕은 물에서 $c = \sqrt{g h_0}$).
- $\gamma$: 점성 감쇠. 크면 꿀, 작으면 물처럼 오래 출렁임 → **"액체 종류" 파라미터**로 노출 가능.
- $F_{\text{tilt}}$: 평형 수면(2.2의 기울어진 직선)으로 끌어당기는 항.
- 이산화: $v_i \mathrel{+}= \big(k(h_{i-1}+h_{i+1}-2h_i) - \gamma v_i + s(h^{eq}_i - h_i)\big)\Delta t$, $h_i \mathrel{+}= v_i\Delta t$
- **수치 안정 조건(CFL)**: $c\,\Delta t/\Delta x \le 1$. 어기면 수면이 폭발적으로 발산한다 — 실제 코딩 때 제일 먼저 부딪히는 버그.
- 부피 보존: 매 프레임 $\sum h_i$를 초기값으로 재정규화(수치 오차로 물이 늘거나 줄지 않게).

> 대안: 입자(모래) 방식(Adafruit PixelDust처럼 픽셀 알갱이가 굴러다님). 도트 느낌은 더 강하지만 "수면"과 "출렁임"은 높이장이 더 액체답다. 프로토타입에서 둘 다 보고 고르자.

### 2.4 자이로는 어디에 쓰나
액체 자체엔 가속도계만으로 충분하다. 자이로(각속도 $\omega$)는 **반응 판정**에 쓴다.
- $|\vec\omega|$ 가 임계값 이상 일정 시간 → 빙글빙글 돌림 → 어지러움 표정
- 저크(가속도 변화율) $|\Delta \vec a/\Delta t|$ 가 큼 → 부딪힘/급정지 → 놀람
- 상보필터로 가속도계+자이로 융합 → 흔드는 중에도 "진짜 아래" 방향이 덜 튀게 함(선택).

## 3. 하드웨어 설계

### 3.1 핵심 부품 후보와 추천

**MCU — 결정: Seeed XIAO ESP32-C3** (ESP32 계열 사용, 마이크·스피커 미사용)
- 21 × 17.5 mm, nRF52840 Sense와 같은 외형 → 케이스 설계를 그대로 재사용 가능.
- **LiPo 충전 회로 내장**, USB-C, Wi-Fi + BLE 5.
- IMU가 칩에 없으므로 **외장 IMU 모듈**(LSM6DSO 또는 LSM6DS3TR-C 브레이크아웃, I²C) 필요 → 부품 1개·배선 몇 가닥 추가(3.2).
- 대안이었던 nRF52840 Sense 대비 트레이드오프: IMU 내장 상실, 딥슬립·액티브 전류 둘 다 nRF52840보다 불리한 경우가 많음(3.3) / 대신 Wi-Fi, 훨씬 흔한 보드라 예제·부품 구하기가 쉬움.
- 참고: XIAO ESP32-**S3**는 카메라 커넥터가 있어 이 프로젝트엔 불필요하게 크고 비쌈 → C3로 충분.

**디스플레이 — 추천: 0.96" 또는 1.3" 단색 OLED(SSD1306/SH1106, 128×64, I²C)**

| 후보 | 도트 느낌 | 전력 | 배선 | 비고 |
|------|-----------|------|------|------|
| **단색 OLED 128×64 (추천)** | 4×4px를 1도트로 → 32×16 도트 | 낮음(~10–20 mA) | 4선(I²C) | 검은 배경이 진짜 꺼짐 → 도트가 떠 보임 |
| 원형 1.28" 컬러 TFT (GC9A01) | 컬러 가능 | 높음(백라이트 ~20–40 mA) | 6–7선(SPI) | 병/구슬 느낌 외형에 최적, 난이도↑ |
| 8×8 / 16×16 LED 매트릭스 | 최고(물리적 도트) | 높음 | 모듈에 따라 | 해상도 부족 or 크기 큼 |

얼굴+액체를 한 화면에 넣으려면 해상도가 최소 32×16 도트는 되어야 해서 OLED가 균형이 제일 좋다.

**배터리**: LiPo 1셀 3.7 V, 150–300 mAh (예: 402030 ≈ 200 mAh, 40×20×4 mm). **보호회로(PCM) 부착형 필수.**

**IMU 모듈 — 추천: LSM6DSO 또는 LSM6DS3TR-C 브레이크아웃 (I²C)**
- OLED와 **같은 I²C 버스를 공유**(SDA/SCL 배선 추가 없음, 전원 2가닥만 더 필요). I²C 주소가 OLED(0x3C)와 겹치지 않아 버스 공유가 문제없음.
- 두 칩 모두 칩 자체 만보기·모션 인터럽트 기능을 가지고 있어, "IMU 칩이 걸음을 세는 동안 MCU는 잠들어 있다"는 설계를 그대로 유지할 수 있음(MODES.md 1절).
- INT 핀을 ESP32-C3의 **RTC GPIO**(딥슬립 웨이크업 가능 핀, 예: GPIO2/3/4)에 연결해야 "움직이면 깨어남"이 딥슬립에서도 동작.

**기타**: 슬라이드 스위치(배터리 차단), (옵션) 택트 스위치, 28–30 AWG 실리콘 전선.

### 3.2 배선(추천 구성 기준)
```
XIAO ESP32-C3                    OLED (I2C)         IMU 모듈 (I2C, 같은 버스)
  3V3 ────────────────────────── VCC ─────────────── VCC
  GND ────────────────────────── GND ─────────────── GND
  D4 (SDA/GPIO6) ──────────────── SDA ─────────────── SDA
  D5 (SCL/GPIO7) ──────────────── SCL ─────────────── SCL
  D3 (GPIO2, RTC GPIO) ─────────────────────────────── INT (모션 인터럽트, 딥슬립 웨이크)

  BAT+ ── 슬라이드 스위치 ── LiPo(+)
  BAT- ───────────────────── LiPo(-)
  D1 ── 택트 스위치 ── GND   (옵션, 내부 풀업)
```
외부 배선이 **OLED 4가닥 + IMU 3가닥(전원 2 + INT 1, SDA/SCL은 OLED와 동일 배선에서 분기) + 배터리 2가닥**. 이 중 OLED 쪽 4가닥을 "노출 포인트"로 쓰기 좋다(4.3 참고). IMU 모듈 전원은 OLED 전원선에서 분기하면 케이스 밖으로 새 구멍을 안 뚫어도 됨.

### 3.3 전력 예산(대략, ESP32-C3 기준 — nRF52840보다 불리)
| 상태 | 전류 | 200 mAh 기준 |
|------|------|--------------|
| 화면 ON, 애니메이션(Wi-Fi/BLE 켠 채 방치) | ~40–80 mA | 약 2.5–5 시간 |
| 화면 ON, **Wi-Fi 꺼서(WIFI_OFF) BLE만 대기** | ~25–35 mA | 약 6–8 시간 |
| 딥슬립, IMU 인터럽트로만 웨이크 | ~0.1–1 mA (실측 필요, 보드 레귤레이터·충전 IC 대기전류 영향) | 수 일~수 주 |

→ ESP32 계열은 라디오 때문에 액티브 전류가 nRF52840 Sense보다 3~5배 높다. **코드에서 Wi-Fi를 명시적으로 끄는 것이 사실상 필수**이고, BLE도 안 쓰는 시간엔 꺼두는 게 좋다. "움직이면 깨어나고 30–60초 가만두면 잠드는" 설계는 그대로 필수이며, 실사용(하루 합계 30분 활성) 기준 충전 주기는 nRF52840안보다 짧아질 수 있어 시제품에서 반드시 실측한다.

## 4. 외형·구조 설계

### 4.1 형태 후보
1. **포켓 게임기형(추천, 1차 시제품)**: 둥근 모서리 사각형, 약 **32 × 48 × 13 mm**. 부품 배치가 쉬움.
2. **병/플라스크형**: 상단 좁은 목(여기에 키링 구멍), 몸통이 화면 → "병 속 캐릭터(C안)" 컨셉과 딱 맞음. 원형 TFT와 조합하면 가장 예쁨.
3. **캡슐/알약형**: 한쪽 끝 투명 창.

### 4.2 적층 구조(단면, 앞→뒤)
```
 ┌───────────── 전면 베젤 (PLA/PETG, 화면 창 뚫림)
 │  투명 창 1 mm (아크릴 레이저컷 or 투명 PETG 인쇄)
 │  OLED 모듈 (~3 mm, 헤더 핀 제거하고 직접 납땜)
 │  IMU 브레이크아웃 (~1.5 mm, OLED 뒤 빈 공간에 배치)
 │  XIAO ESP32-C3 (~3.5 mm, 뒷면 USB-C 구멍)
 │  LiPo (~4 mm, 양면테이프로 고정)
 └───────────── 후면 커버 (~1.2 mm)
 총 두께 ≈ 12–14 mm
```
- 결합: **M2 나사 + 열압입 인서트(heat-set insert)** 2개 추천. 스냅핏은 PLA에서 반복 개폐 시 금방 깨짐.
- IMU 축 방향: IMU 모듈을 화면과 평행하게 고정하고, 코드에서 축 매핑(x↔y 부호)을 한 번 보정.

### 4.3 노출 전선 포인트 설계
- **OLED I²C 4가닥을 케이스 옆면 홈(채널) 밖으로 빼서 반대편으로 다시 넣는** 구조. 색: VCC 빨강 / GND 검정 / SDA 파랑 / SCL 노랑 → 기능이 보이는 디자인.
- 홈 폭 = 전선 외경 + 0.2 mm로 설계해 **끼워 고정**(접착제 최소화).
- 출입구 모서리는 반드시 **R ≥ 0.5 mm 필렛** → 반복 굽힘으로 피복이 찢어지는 것 방지(키체인은 하루 수백 번 흔들린다).
- **배터리 선은 절대 노출하지 않는다.** 피복 손상 시 단락 = 발열/화재. 노출은 저전류 신호선만.
- 대안 연출: 투명 창 너머로 보이는 내부 배선 / 옆면에 FFC(평판 케이블) 노출.

### 4.4 키링 고리 — 3D 프린팅 강도
FDM 출력물은 **층과 층 사이(Z방향)가 가장 약하다.** 고리는 반드시 **출력 평면(XY) 안에 눕혀서** 인쇄해 당기는 힘이 층 내부 필라멘트를 따라 걸리게 할 것. 고리 벽 두께 ≥ 2.5 mm, 가능하면 금속 D링/분할링이 걸리는 부분에 **금속 아일렛**이나 M2 나사 기둥을 관통시켜 보강.

### 4.5 프린터·재료 메모(구매 예정 기준)
- 이 크기 부품이면 소형 베드 프린터(예: 180 mm급)로 충분.
- 재료: 1차 PLA(치수 확인용) → 최종 **PETG**(충격·열에 강함, 여름 차 안 PLA 변형 방지).
- 공차: 끼워맞춤 +0.2 mm, 나사 구멍은 인서트 규격대로.

## 5. 소프트웨어 구조

```
loop (30–60 FPS):
  읽기   : IMU(accel, gyro)
  판정   : 이벤트 감지(흔들기, 회전, 충격, 뒤집기, 낙하, 무움직임)
  상태   : 표정 상태머신 갱신
  물리   : 액체 높이장 1스텝 (2.3)
  렌더   : 액체 → 얼굴(눈 위치는 g벡터 방향으로 오프셋) → OLED 전송
  절전   : 무움직임 T초 → 화면 OFF, IMU wake 인터럽트 설정, 딥슬립
```

**표정 상태머신(초안)**
```
IDLE ──(무작위 2–6 s)──▶ BLINK ──▶ IDLE
IDLE ──(무작위 10–20 s)─▶ LOOK_AROUND ─▶ IDLE
IDLE ──(무움직임 30 s)──▶ SLEEPY ──(추가 30 s)──▶ SLEEP(화면 OFF)
ANY  ──(|ω| 큼, 1 s 지속)─▶ DIZZY(@_@) ──(3 s)──▶ IDLE
ANY  ──(저크 큼)──────────▶ SURPRISED(O_O) ─▶ IDLE
ANY  ──(g_y 반전=뒤집힘)──▶ UPSET ─▶ 원위치 시 IDLE
SLEEP ─(모션 인터럽트)────▶ WAKE_UP(기지개) ─▶ IDLE
```
- 눈깜빡임 간격은 고정값이 아니라 **지수분포 난수**로 → 사람 눈에 "살아있는" 느낌(규칙적이면 기계처럼 보임).
- 개발 환경: Arduino IDE(ESP32 보드 패키지) 또는 PlatformIO, 라이브러리 `U8g2`(OLED), `Adafruit LSM6DS`/`FastIMU`(IMU). 부팅 초기에 `WiFi.mode(WIFI_OFF)`로 라디오를 꺼서 대기전류를 낮추는 코드를 첫 스케치부터 넣는다.

## 7. 개발 로드맵

4. **P3 — 통합/절전**: 딥슬립·모션 웨이크, 배터리 실측.
5. **P4 — 최종 출력**(PETG) + 노출 전선 마감.
