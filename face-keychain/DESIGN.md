# 표정 변화 키체인 설계 (Face-Display Keychain)

첨부 사진 구조(캐리비너 + 커넥터 + 소형 OLED + 배터리 모듈)를 기준으로,
"왜 이렇게 설계하는가"부터 잡고 내려간다. 부품 선정 → 회로 → 전력 계산 → 펌웨어 순.

---

## 1. 시스템 구조 (원리)

블록으로 쪼개면 이 키체인은 4개 서브시스템의 직렬 연결이다.

```
[Li-Po 배터리] → [충전/보호 회로] → [전원 스위치] → [MCU] --I2C--> [OLED]
                        ↑
                   [USB-C 충전 입력]
```

- **배터리**: 에너지 저장. 리튬폴리머(LiPo)는 단위 부피당 에너지밀도가 높아 소형 웨어러블의 사실상 표준.
- **충전/보호 회로(TP4056 등)**: 배터리를 과충전(>4.2V)·과방전(<3.0V)·과전류로부터 보호. 이게 없으면 배터리가 부풀거나(스웰링) 발화 위험.
- **스위치**: 대기 전류(quiescent current)를 완전히 차단해 보관 중 방전을 막음.
- **MCU**: 로직 처리 + I2C 마스터.
- **OLED**: 자체발광 디스플레이. 백라이트가 없어 "꺼진 픽셀 = 전류 0"이라는 특성이 배터리 수명에 유리 (아래 4장에서 정량화).

사진 속 4가닥 배선(빨강/검정/파랑/초록)이 정확히 OLED 모듈의 `VCC, GND, SCL, SDA` 4핀과 대응한다.

## 2. 부품 선정 (BOM)과 근거

| 부품 | 추천 | 선정 이유 |
|---|---|---|
| MCU | **Arduino Pro Mini 3.3V/8MHz** (ATmega328P) | 3.3V 버전은 LiPo 전압(3.0~4.2V) 범위를 **레귤레이터 없이 직접 커버**. 8MHz 클럭은 3.3V에서 스펙상 안전 동작 한계(데이터시트: 저전압일수록 최대클럭 낮춤) |
| 디스플레이 | **SSD1306 0.66"~0.96" OLED, I2C, 128×32 또는 128×64** | 소형, 저전력, I2C라 배선 4가닥으로 끝남 (SPI 대비 배선 수 절반) |
| 배터리 | **LiPo 3.7V 100~150mAh** (파우치형) | 키체인 크기 제약상 100mAh급이 현실적. 사진의 주황색 파우치가 이 타입 |
| 충전/보호 | **TP4056 + 보호회로 일체형 모듈 (USB-C)** | 충전 IC + 과방전 보호 MOSFET이 한 보드에 있어 배선 실수 위험이 적음 |
| 스위치 | **슬라이드 or 푸시 래치 스위치** | 배터리 OUT+ 라인에 직렬 삽입 (충전 경로는 건드리지 않음, 아래 3장 참고) |
| 부착 | **카라비너 + 열쇠고리 (사진처럼)** | 순수 기구부 |

> MCU를 ESP32 계열로 바꾸면 Wi-Fi/BLE로 "폰에서 표정 원격 전송"까지 확장 가능하지만, 대기전류가 Pro Mini 대비 수십~수백 배라 100mAh 배터리로는 하루도 못 간다. **저전력이 최우선이면 ATtiny85/Pro Mini, 기능 확장이 최우선이면 ESP32-C3** — 트레이드오프로 기억할 것.

## 3. 회로 설계 (전력 경로가 핵심)

```
                +-------------------+
  USB-C ------->|  TP4056 (충전IC)   |
                |  B+ B- OUT+ OUT-  |
                +---+-----------+---+
                    |           |
                 [LiPo+]     [스위치]---+
                    |                  |
                 [LiPo-]           OUT+(스위치 후)
                    |                  |
                    +------------------+---> MCU VCC (3.3V 핀)
                    |                       (LiPo를 레귤레이터 없이 직결)
                    +---------------------> MCU GND

  MCU ---SCL---> OLED SCL
  MCU ---SDA---> OLED SDA
  MCU ---VCC---> OLED VCC
  MCU ---GND---> OLED GND
```

**설계 포인트 (원리):**

1. **스위치는 반드시 OUT+ (충전 IC 이후, 배터리와 직결이 아닌 부하 쪽)에 넣는다.**
   B+ 쪽에 넣으면 충전 중 스위치를 꺼도 의미가 없고, 배터리와 보호회로 사이를 끊으면 보호회로가 배터리 상태를 못 읽어 오동작할 수 있다.
2. **I2C는 오픈드레인 + 풀업 저항이 원리.** SSD1306 모듈 보드에는 보통 4.7kΩ 풀업이 이미 내장되어 있어 별도 저항 불필요 — 하지만 모듈 두 개 이상을 한 버스에 물릴 계획이 없다면 신경 쓸 부분 아님.
3. **디커플링 커패시터**: MCU VCC-GND 사이 100nF 세라믹 1개는 넣는 걸 권장. 배터리 임피던스가 높아 OLED 리프레시 시 전류 스파이크가 전압을 흔들 수 있음 (OLED 자체 모듈에도 보통 있음).

## 4. 전력 계산 (배터리 수명 — 물리적으로 짚기)

배터리 수명 추정의 핵심 식은 단순하다.

```
사용 시간 T = Q(용량, mAh) / I_avg(평균 전류, mA)
```

여기서 **I_avg가 시간에 따라 변하므로(디스플레이가 계속 안 켜져 있으므로) 시간가중 평균**을 써야 한다:

```
I_avg = Σ (I_k · t_k) / Σ t_k
```

예시 수치 (SSD1306 128×64, 대비 낮춰 사용 가정):
- MCU(8MHz, 3.3V) 활성: ~4 mA
- MCU 슬립(idle, 타이머만 깨어있음): ~1 mA (Pro Mini는 보드에 전원 LED·레귤레이터가 남아있으면 실제로 훨씬 높음 → **보드 위 전원 LED와 레귤레이터를 물리적으로 떼어내는 것이 저전력 개조의 핵심**)
- OLED, 흰 픽셀 비율 30% 기준: ~10~15 mA (검은 배경일수록 전류가 낮은 게 OLED의 물리적 특성 — 픽셀이 꺼지면 그 서브픽셀엔 전류가 안 흐름)

평균을 대략 I_avg ≈ 12mA로 잡으면:

```
T = 120mAh / 12mA = 10시간
```

**실전 적용 (설계 전략):**
- 배터리 용량을 2배(200mAh)로 올리면 수명도 거의 선형으로 2배 — 부피 제약과 트레이드오프.
- 화면을 항상 켜두지 않고, "주기적으로 켰다 끄는" 듀티비 D를 도입하면 I_avg = D·I_on + (1-D)·I_sleep로 낮아짐. 예: 5초 표정 표시 후 3초 화면 꺼짐 반복(D=0.625)이면 체감 애니메이션은 유지하면서 평균 전류를 낮출 수 있음.
- 가장 큰 손실은 보통 **레귤레이터/LED 대기전류**이지 MCU 코어 자체가 아니다 — 회로 최적화 시 이 부분부터 확인.

## 5. 펌웨어 설계 (표정이 바뀌는 원리)

OLED는 프레임버퍼(SSD1306의 경우 128×64비트 = 1KB) 전체를 MCU RAM에 들고 있다가 `display()` 호출 시 I2C로 통째로 전송하는 구조다. 그래서 "표정을 바꾼다" = **매 프레임 buffer를 지우고 도형을 다시 그린 뒤 전송**하는 것.

애니메이션은 `delay()`를 쓰면 안 된다 — 배터리 절전/인터럽트와 상충하고 반응성도 떨어짐. **상태 머신 + `millis()` 논블로킹 스케줄러**가 원리적으로 맞는 방식이다 (아래 코드에 구현).

상태 정의:
- `NORMAL`: 눈 두 개 (사진과 동일한 사각형 눈)
- `BLINK`: 일정 확률로 진입, 눈 높이를 0으로 줄였다가 복원 (사람 눈꺼풀의 개폐를 y축 스케일로 근사)
- `HAPPY`: 눈이 아치형(^) — 사진 속 상단의 노란 반원과 유사한 곡선
- `LOVE`: 하트 모양 눈 — "여자친구용" 특화 표정, 일정 주기로 등장
- `SLEEPY`: 눈이 반쯤 감긴 상태(높이 절반) — 장시간 무동작 시 진입, 배터리 절약 신호 겸용

전이는 확률 기반 랜덤 타이머로 처리해 "살아있는" 느낌을 준다 (사람 눈 깜빡임 간격이 불규칙한 것과 동일한 이유).
